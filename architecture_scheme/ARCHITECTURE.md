Команда `exit` имеет особое поведение в пайплайнах:

- **Завершает весь shell** - не только пайплайн, а всю сессию
- Если `exit` встречается где угодно в пайплайне (в начале, середине или конце), вся сессия shell завершается
- **Обнаруживается до исполнения**: Repl проверяет наличие `exit` в списке команд перед вызовом `Pipeline.execute()`
- Пайплайн не выполняется, если найдена команда `exit`

```bash
> echo hello | exit | cat

# Shell завершается - пайплайн не выполняется
```

## Встроенные команды

Проект содержит собственные реализации следующих команд:
- `echo` - вывод аргументов на stdout
- `cat` - вывод содержимого файлов или чтение из stdin
- `wc` - подсчет строк, слов и байт в файлах или stdin
- `pwd` - вывод текущего рабочего каталога
- `cd` - смена текущего рабочего каталога
- `ls` - вывод содержимого директории
- `grep` - поиск текста с поддержкой регулярных выражений, границ слов, регистронезависимого поиска и контекста

Команды `echo`, `cat`, `wc`, `pwd` и `grep` компилируются как отдельные бинарные файлы в директории `target/release/`.
У команд `exit`, `help`, `cd` и `ls` своих исполняемых файлов нет - их логика выполняется прямо в read-execute-print-loop (repl).

### Реализация команды grep

Команда `grep` использует библиотеку **clap v4.5** для парсинга аргументов командной строки и предоставляет следующие возможности:

#### Поддерживаемые флаги:
- `-w, --word-regexp` - поиск только целых слов (с использованием Unicode-aware границ слов `\b`)
- `-i, --ignore-case` - регистронезависимый поиск
- `-A, --after-context <NUM>` - вывод NUM строк после каждой найденной строки

#### Выбор библиотеки clap для парсинга аргументов

**Clap (Command Line Argument Parser)** была выбрана библиотека  по следующим причинам:

1. **Широкое сообщество и экосистема**: clap - это самая популярная библиотека для CLI в Rust (более 50 млн загрузок), что гарантирует активную поддержку, обширную документацию и множество примеров использования.

2. **Derive-макросы (процедурные макросы)**: clap позволяет декларативно описать структуру аргументов через derive-атрибуты (`#[derive(Parser)]`), что существенно сокращает количество boilerplate-кода. Вместо ручного парсинга можно описать структуру `Args` с полями и аннотациями, а clap автоматически генерирует весь код парсинга

3. **Типобезопасность**: все аргументы парсятся в строготипизированную структуру Rust. Это означает, что на этапе компиляции гарантируется корректность типов (например, `after_context: Option<usize>` автоматически конвертируется из строки в число с валидацией)

4. **Автоматическая генерация справки**: clap автоматически генерирует сообщения `--help` и `--version` на основе описаний в коде, включая форматирование, группировку опций и примеры использования. Это избавляет от необходимости вручную поддерживать документацию в актуальном состоянии.

5. **Поддержка различных форматов**: clap поддерживает короткие (`-w`) и длинные (`--word-regexp`) формы флагов, позиционные аргументы, множественные значения, значения по умолчанию и многое другое из коробки.

6. **Производительность**: clap компилирует парсинг на этапе компиляции через макросы, что делает runtime-парсинг очень быстрым без overhead рефлексии или динамического анализа.


**Альтернативы, которые рассматривались:**
- `structopt` - предшественник clap v3+, интегрирован в clap
- `getopts` - более низкоуровневая библиотека, требует больше ручного кода
- `docopt` - парсинг через описание в формате docopt, менее типобезопасен
- Ручной парсинг через `std::env::args()` - слишком трудоёмко и подвержено ошибкам

#### Архитектура реализации:
```
GrepEngine (основной движок)
├── regex: Regex (скомпилированное регулярное выражение)
├── after_context: Option<usize> (количество строк контекста)
└── multiple_files: bool (флаг множественных файлов)

Args (структура аргументов clap)
├── pattern: String (регулярное выражение для поиска)
├── files: Vec<String> (список файлов для поиска)
├── word_regexp: bool (флаг -w)
├── ignore_case: bool (флаг -i)
└── after_context: Option<usize> (флаг -A)
```

#### Алгоритм работы:
1. **Парсинг аргументов**: clap автоматически парсит командную строку в структуру `Args`
2. **Создание движка**: `GrepEngine::new()` компилирует регулярное выражение с учетом флагов `-w` и `-i`
3. **Обработка входных данных**:
   - Если указаны файлы: читает каждый файл построчно
   - Если файлы не указаны: читает из stdin
4. **Поиск и вывод**: для каждой строки проверяет совпадение с регулярным выражением и выводит результаты с контекстом

#### Особенности реализации:
- **Пересекающиеся контексты**: корректно обрабатывает случаи, когда области контекста пересекаются (не дублирует строки)
- **Разделители групп**: между разными группами совпадений выводится разделитель `--`
- **Unicode поддержка**: использует Unicode-aware границы слов и регистронезависимый поиск
- **Обработка ошибок**: корректная обработка несуществующих файлов и некорректных регулярных выражений

### Реализация команд cd и ls

Команды `cd` и `ls` реализованы как встроенные команды в REPL, поскольку они работают с состоянием shell (текущей рабочей директорией).

#### Команда cd (change directory)

Команда `cd` изменяет текущую рабочую директорию shell-сессии:

**Возможности:**
- Переход в абсолютную директорию: `cd /path/to/dir`
- Переход в относительную директорию: `cd ../parent` или `cd subdir`
- Переход в домашнюю директорию: `cd` (без аргументов)
- Навигация с использованием `..` и `.`: `cd ../../..`

**Архитектура:**
- Текущая директория хранится в `Init.current_dir: PathBuf`
- Методы управления:
  - `Init::change_dir(&mut self, path: &str)` - изменяет директорию относительно текущей
  - `Init::set_current_dir(&mut self, dir: PathBuf)` - устанавливает абсолютный путь
  - `Init::current_dir(&self)` - возвращает текущую директорию

**Обработка путей:**
- Использует `std::fs::canonicalize()` для разрешения относительных путей и символических ссылок
- Валидирует существование директории перед сменой
- Проверяет, что целевой путь является директорией (не файлом)

**Обработка ошибок:**
- `cd: {path}: No such file or directory` - если путь не существует
- `cd: {path}: Not a directory` - если путь указывает на файл
- `cd: HOME not set` - если вызвано `cd` без аргументов, но переменная HOME не установлена

#### Команда ls (list directory contents)

Команда `ls` выводит содержимое директории в отсортированном виде:

**Возможности:**
- Вывод содержимого текущей директории: `ls`
- Вывод содержимого указанной директории: `ls /path/to/dir`
- Вывод информации о файле: `ls file.txt` (выводит имя файла)
- Поддержка относительных и абсолютных путей

**Архитектура:**
- Реализована в методе `Repl::handle_ls()`
- Использует `std::fs::read_dir()` для чтения содержимого директории
- Путь разрешается относительно `Init.current_dir`

**Алгоритм работы:**
1. Если аргумент не указан: использует `Init.current_dir`
2. Если аргумент указан:
   - Абсолютный путь (начинается с `/`): использует как есть
   - Относительный путь: разрешает относительно `Init.current_dir`
3. Проверяет существование пути
4. Если это файл: выводит только имя файла
5. Если это директория: читает содержимое, сортирует по алфавиту и выводит построчно

**Обработка ошибок:**
- `ls: {path}: No such file or directory` - если путь не существует
- `ls: {path}: {error}` - при ошибках чтения директории

**Особенности:**
- Вывод отсортирован по алфавиту
- Каждая запись выводится на отдельной строке
- Показывает и файлы, и поддиректории без различия 

## Как создаются команды
Сырой пользовательский ввод проходит через многоэтапный конвейер обработки:

1. `InputProcessor.process()` получает строку от пользователя
2. `Tokenizer.tokenize()` разбивает строку на токены, учитывая кавычки и экранирование
3. `split_on_pipes_tokens()` делит токены по символу `|` для создания пайплайнов
4. Для каждой части пайплайна:
   - `QuoteHandler.handle()` обрабатывает и удаляет кавычки
   - `Expander.expand_tokens()` подставляет переменные окружения (поддерживает `$VAR` и `${VAR}`)
   - `CommandProducer::produce_command()` анализирует перенаправления (`<`, `>`, `>>`, `2>`, `2>>`, `1>`, `1>>`) и формирует структуру Command

Результат: `Vec<Command>` готовых к исполнению команд с настроенными перенаправлениями.

## Как исполняются команды и работают перенаправления?

Реализация с пайплайнами работает следующим образом:

1. `REPL.run()` - главный цикл обработки пользовательского ввода
2. `InputProcessor.process()` возвращает `Vec<Command>` (может содержать несколько команд для пайплайна)
3. REPL проверяет наличие встроенных команд:
   - Если найдена команда `exit` (в любом месте пайплайна) - завершает shell
   - Если это одиночная команда `help` - показывает справку
   - Если это одиночная команда `cd` - изменяет текущую директорию через `Init.change_dir()`
   - Если это одиночная команда `ls` - выводит содержимое директории через `Repl.handle_ls()`
4. `Pipeline.execute()` получает `Vec<Command>`, `Environment` и `current_dir` и выполняет:
   - Одиночная команда: исполняется напрямую через `Runner`
   - Пайплайн команд: последовательно соединяет команды через stdout→stdin

### Детали работы Pipeline

`Pipeline` - специализированный модуль для исполнения цепочек команд:

Для одиночной команды:
- Вызывает `prepare_command()` для настройки перенаправлений
- Передает команду в `Runner.execute()` вместе с `current_dir`

Для пайплайна команд (cmd1 | cmd2 | cmd3):
1. Первая команда:
   - stdin: из файла (если `< file`) или пустой
   - stdout: передается следующей команде (pipe)
   - stderr: независим (в терминал или файл, если `2> file`)
2. Промежуточные команды:
   - stdin: получает от предыдущей команды
   - stdout: передается следующей команде
   - stderr: независим
3. Последняя команда:
   - stdin: получает от предыдущей команды
   - stdout: в терминал или файл (если `> file`)
   - stderr: независим

### Настройка перенаправлений в Runner

`Runner.execute()` определяет тип исполнения и настраивает потоки:

1. Тип команды:
   - Собственные бинарники: ищет в `bin_path` (например, `target/release/echo`)
   - Системные команды: запускает через системный PATH как fallback

2. Установка рабочей директории:
   - Все команды выполняются в контексте `current_dir` через `cmd.current_dir(current_dir)`
   - Это позволяет командам работать с относительными путями относительно текущей директории shell

3. Перенаправления:
   - `stdin`: передается как `Stdio::piped()` с записью данных в `child.stdin`
   - `stdout`: при наличии файла создается `File` и устанавливается `cmd.stdout(Stdio::from(file))`, поддерживает режимы overwrite/append
   - `stderr`: аналогично stdout, поддерживает режимы overwrite/append
   - Режимы открытия файлов: `create(true).write(true).truncate(true)` для `>` и `create(true).append(true)` для `>>`

4. Исполнение: каждая команда запускается в отдельном процессе через `std::process::Command`


## Как представляются переменные окружения

Переменные окружения представляют собой `Environment`, живущий внутри `Init`. Он передается везде где нужно по ссылке (мутабельной):

```rust
pub struct Environment {
    vars: HashMap<String, String>
}

impl Environment {
    pub fn new() -> Self                        // пустое окружение
    pub fn with_vars(vars: HashMap<String, String>) -> Self  // из HashMap
    pub fn capture_current() -> Self            // захват системных переменных
    pub fn get(&self, key: &str) -> Option<&str>
    pub fn set<K, V>(&mut self, k: K, v: V) 
    pub fn remove(&mut self, k: &str)
}
```

## Основные модули в архитектуре CLI

### Инициализация и главный цикл:
- `Init` - настройка путей к бинарникам, переменных окружения и текущей рабочей директории
- `Repl` - главный REPL (read-execute-print-loop) цикл, обработка пользовательского ввода

### Парсинг и обработка команд:
- `Tokenizer` - разбиение строки на токены с учетом кавычек и экранирования
- `QuoteHandler` - обработка одинарных `'` и двойных `"` кавычек  
- `Expander` - расширение переменных окружения (`$VAR`, `${VAR}`) с longest-match алгоритмом
- `CommandProducer` - создает структуры Command (занимаясь в т.ч. парсингом информации для перенаправления потоков)
- `InputProcessor` - фасад, координирует весь процесс парсинга

### Исполнение:
- `Pipeline` - управляет исполнением цепочек команд (пайплайнов), соединяет stdout→stdin
- `Runner` - исполняет отдельные команды (собственные бинарники или системные команды)
- `Command` - структура данных для представления готовой к исполнению команды
- `Environment` - переменные окружения и манипуляции с ними

### Разделение ответственности

- `Repl` - управляет REPL циклом и пользовательским вводом, обрабатывает встроенные команды (`exit`, `help`, `cd`, `ls`), распознает присваивание переменных
- `Pipeline` - отвечает за исполнение цепочек команд с правильным соединением потоков, управляет передачей данных между командами
- `Runner` - исполняет отдельные команды (системные и собственные), настраивает перенаправления I/O и рабочую директорию
- `InputProcessor` - парсит ввод в структуры Command, делит на пайплайны
- `Environment` - хранит переменные окружения и предоставляет методы для работы с ними
- `Command` - структура данных для представления готовой к исполнению команды

### Исполнение пайплайна

**Одиночная команда:**
```rust
Pipeline.prepare_command() // настраивает перенаправления
  -> Runner.execute(cmd, env_vars, current_dir)  // исполняет команду
  -> Result<String, String> // возвращает результат
```

### Примеры использования пайплайнов

```bash
# Чтение из файла, фильтрация, сортировка, запись в файл
> cat < input.txt | grep "pattern" | sort > output.txt

# Независимое перенаправление stderr для каждой команды
> cmd1 2> errors1.log | cmd2 2> errors2.log | cmd3 2> errors3.log

# Комбинация перенаправлений stdout и stderr
> cat file.txt | grep "error" > errors.txt 2> error.log

# Подсчет строк с определенным паттерном
> cat data.txt | grep "ERROR" | wc -l
```

### Команда exit в пайплайнах

Команда `exit` имеет особое поведение в пайплайнах:

- Завершает весь shell
- Если `exit` встречается где угодно в пайплайне (в начале, середине или конце), вся сессия shell завершается
- Shell обнаруживает `exit` перед выполнением пайплайна

Пример:
```bash
> echo hello | exit | cat
Goodbye!
```

### Возвращаемые значения и обработка ошибок

- Каждая команда в пайплайне выполняется независимо
- Если команда завершается с ошибкой (ненулевой код возврата), последующие команды продолжают выполняться
- Пайплайн не прерывается при ошибках - это отличается от поведения в bash с `set -o pipefail`
- Сообщения об ошибках выводятся в stderr (который идет в терминал независимо от пайпа)
- Команда, получившая ошибку, передает пустой вывод следующей команде

Пример:
```bash
> cat nonexistent.txt | wc -l
cat: nonexistent.txt: No such file or directory
       0       0       0
```

## Потоки данных в архитектуре

```
Пользователь
    ↓
[Repl.run()]
    ↓
[InputProcessor.process()]
    ↓
[Tokenizer → QuoteHandler → Expander → CommandProducer]
    ↓
Vec<Command> (может быть пайплайн)
    ↓
[Repl проверяет exit/help/cd/ls]
    ↓
    - exit: завершает shell
    - help: показывает справку
    - cd: изменяет Init.current_dir
    - ls: выводит содержимое директории
    ↓
[Pipeline.execute(Vec<Command>, Environment, current_dir)]
    ↓
Для каждой команды:
    ↓
[Pipeline.prepare_command()] → настройка stdin/stdout/stderr
    ↓
[Runner.execute(Command, Environment, current_dir)]
    ↓
    - устанавливает рабочую директорию через cmd.current_dir()
    - настраивает перенаправления I/O
    ↓
[std::process::Command] → исполнение
    ↓
stdout → следующей команде (или терминалу для последней)
stderr → терминал (независимо)
    ↓
Результат возвращается пользователю
```
